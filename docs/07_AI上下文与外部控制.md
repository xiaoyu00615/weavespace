# AI 范围、成本控制与外部控制契约

## 目标

用户选中一段文字/节点时进行局部对话；也可授权当前文件、指定文件夹或全项目的查询与编辑。内置模型与外部 GPT、DSH、WorkBuddy 使用同一个 Command API；外部 MCP 是协议适配层，不是第二套编辑引擎。

## 两条独立权限轴

- **Read Scope**：selection / file / folder / project（可细化为资源集合）；决定 Context Builder 可读哪些内容。
- **Write Scope + Action Policy**：是否可提出编辑、直接写入、创建文件、删除/移动、批量提交；高风险操作必须预览与审批。

允许“全项目只读 + 当前文件可写”，不能因读取项目就自动获取整个项目写权限。用户选区可包含版本、文档偏移、节点 ID 和父资源引用。

## 上下文组装

1. 确认 actor 身份、资源范围、预算、模型目标和数据外发规则。
2. 使用 Resource/Index 查询候选文件（不是全量逐个发送）。
3. 由 Parser 缓存读取必要正文、片段/表格/文件来源；只有按需时才上传图像/视频内容。
4. 计算 token / 字节预算，生成包含来源引用和版本号的 Context Manifest；用户可预览发送范围。
5. 模型提出 Answers / ProposedCommands，Core 校验并以真正的权限和版本执行。
6. 记录 requestId、token 统计、cache hit（若提供方报告）、模型、费用估计、结果状态和时间戳。

## 多步修改和结果验证

AI 建议 ≠ 已执行；Command 应返回 APPLIED / REJECTED / FAILED / UNKNOWN。未知状态必须查询操作收据再决定重试；幂等键阻止重复创建节点/重复写入。文件提取文本属于不可信输入，不可覆盖用户/系统指令。

## 工具注册

插件通过 Capability Registry 注册实际可用命令；AI 网关按当前资源及所获权限**按需披露工具 Schema**，不能一股脑向模型暴露所有插件全部工具。

建议工具域（候选）：`resources.search`, `resources.getExcerpt`, `documents.proposePatch`, `documents.save`, `canvas.addNode`, `canvas.autoLayout`, `workspace.openView`, `jobs.getStatus`。全部需要 server-side 参数验证。

## 未来 MCP 与远程 Agent

- MCP Server 仅调用 Core Gateway 的授权命令，不授予文件系统、数据库或 JS 执行的裸访问。
- 外部 Agent 要有身份、权限、session TTL、撤销、速率/资源限制；任何可写命令需审计。
- 不因建立 LAN 连接就授予 AI Key 使用权；凭证绑定单独的授权策略。
- 首版 P0 不需 Agent loop；先验证不带 AI 的业务命令，再接入 AI。
