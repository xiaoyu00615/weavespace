# Storage Providers、LAN、权限与安全边界

## Storage Provider（候选）

统一 `list/stat/read/writeConditional/watch/capabilities`，资源支持 local/remote/read-only/virtual；不同 Provider 对 `watch`、原子写入、ETag、离线、速率和权限能力作出显式声明。URI 只是标识，不是授权令牌。

- Local：Windows 本地目录，优先首版实现。项目根是授权边界；符号链接、`..`、大小写/路径规范化、网络共享盘都要按真实路径做访问检查。
- GitHub：先由 Git 插件对本地 clone 工作树操作，分支/提交/推送是 Git 能力；不要把每次编辑变成直接 GitHub API 写文件。
- 云盘/WebDAV/S3：后续 Provider；支持按需下载、版本检查、明确离线/冲突策略。

## LAN 默认关闭

- 首版只绑定 127.0.0.1；未来开启 LAN 时显式选择绑定地址、设备访问/账号和资源范围。
- 采用身份认证、资源级访问控制、时间限制/撤销、传输保护；不能仅依赖内网 IP 白名单。
- 项目/文件夹/文件/动作分层授权；查询结果、缩略图、全文索引、文件下载、事件订阅全部按 ACL 过滤。
- 预览/下载分开授权，但“只读预览”不等于内容无法被复制。
- LAN 客户端不直连 SQLite 数据库，全部经 Host API。断线需基于版本/快照重新同步，不能假定 WebSocket 不丢包。

## 权限与安全威胁

- Path Traversal、软链接逃逸、归档炸弹、恶意 HTML/脚本、伪造 MIME、解析器漏洞。
- SSRF/远程资源拉取与隐私外泄：外部 URL、嵌入内容和 AI 外发使用白名单与审批。
- 受限 HTML 预览独立沙箱/不启用不必要脚本，禁止接触 Host API。
- 插件 manifest 不能证明可信；第三方插件未来需要隔离和资源预算。
- API 密钥、SSH 私钥、Token 存在操作系统凭据库或用户私密配置中；绝不写日志、提交 Git、嵌入画布文件。
- 远程 AI 不因可读就有写入/执行权限；执行文件/命令属于独立高风险能力。

## 权威写入与竞争处理

本地 Host 单一权威管理资源版本和命令序列；多个用户/AI 客户端的写入必须经过同一写入协调。跨进程修改文件要监测冲突；Git 分支合并与 WeaveSpace 文档版本冲突是不同层面的概念。

## 共享未来检验

“电脑 A 共享《向前一步》/人物只读，电脑 B 访问时不得读取其他目录；关闭授权后旧链接和事件订阅均失效；本地用户可以继续工作；日志有 actor/时间/资源范围。”
