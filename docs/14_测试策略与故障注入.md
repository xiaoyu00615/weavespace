# 测试策略与可靠性门槛

## 测试分层

1. Contract：插件清单、数据 schema、错误码、命令/权限规则。
2. Unit：每个模块在假依赖下测试成功/失败、没有隐式全局状态。
3. Integration：Storage → Session → Serializer → Command → Audit 的真实链路。
4. E2E：Shell 分屏、插件切换、关闭重开、异常恢复。
5. Fault Injection：主动制造冲突、异常、崩溃、断线、磁盘错误。
6. Architecture Tests：禁用跨模块内部路径 import，循环依赖，检查公开 API 兼容。

## P0 最低验收矩阵

| Case | 触发 | 期望（必验证） |
|---|---|---|
| CT-01 | 安装 Markdown 插件 | 被发现/校验/激活；记录耗时和时间 |
| CT-02 | 同文件两个视图 | 更新不丢状态、不生成两份独立缓冲 |
| CT-03 | 保存成功 | `SAVE_COMMITTED` + 内容/版本正确 |
| CT-04 | 外部文件已变 | 拒绝覆盖，显示冲突，保留 dirty |
| CT-05 | 文件权限拒绝 | 无持久化副作用，错误码可追踪 |
| CT-06 | 保存时异常/磁盘故障 | 不伪称成功，可恢复或报告 UNKNOWN |
| CT-07 | 重复命令 idempotencyKey | 不重复创建副作用 |
| CT-08 | 插件故障 | 未保存内容受保护；Core 可诊断 |
| CT-09 | 非授权 actor 写入 | 服务端拒绝并记录 audit |
| CT-10 | 重启恢复 | 根据真实提交/草稿状态恢复，不猜测 |
| CT-11 | 新增独立查看器插件 | 不修改已有功能实现源文件 |
| CT-12 | 错误日志 | 有 UTC 时间、traceId、operationId、module、errorCode |

## E 阶段扩展测试

- 稳定 ID：移动、重命名、复制、大小写变化、符号链接、路径逃逸。
- 自定义格式：未知 version/字段、无损 re-save/安全只读、迁移失败回退。
- Derived 缓存：源文件不变但解析器版本变、人工 Confirmed 不被覆盖。
- Remote：事件丢失后重新同步、断网重连、只读授权被撤销、不同用户访问隔离。
- AI：读范围与写范围不同，外发限制、超 Token 预算、模型回应成功但写入失败。
- 插件隔离：异常文件解析、内存/时间超限，非可信代码执行边界。
- 备份：备份成功后真实恢复、数据库 schema 升级中断、安全模式启动。

## 交付记录模板

```text
Task: P0-CT-04
Commit: <git commit sha>
Environment: <node, OS, plugin version>
StartedAt(UTC): ...
FinishedAt(UTC): ...
Result: PASS / FAIL / BLOCKED
TraceId: ...
Evidence: <一段必要日志/输出，脱敏>
Notes: <发现和下一步>
```

没有执行的测试标为 NOT_RUN，不得用“设计满足”“目测正常”代替 PASS。
