# 可观测性、诊断与时间规范（强制）

## 统一三类记录，拒绝重复服务

1. **Operational Logs**：JSONL 结构化日志；可轮转/删旧日志，不作为真实业务状态源。
2. **Audit Records**：谁/何时/对什么资源执行什么操作、判定及最终结果；权限控制和保留策略独立。
3. **State / Command Receipts**：作业/命令与文件的实际持久化状态，由拥有者负责；不可从审计或日志猜测成功。

Metrics/Traces 由同一 Observability 基础产生，初版可轻量实现；不要新建另外一套业务记录系统。

## 必须字段

`timestamp`（UTC ISO 8601）、`level`、`module`、`event`、`runId`、`traceId`、`operationId`（重要操作）、`resourceId`（若涉及文件）、`actorId`（审计），`result`/`errorCode`（终态），`durationMs`（耗时任务）。

可选：`deviceId`（非识别性内部标识）、`pluginId/version`、`jobId`、`documentRevision`、`sourceVersion`、`sequence`（限定事件流域）。示例见 `examples/log-event.json`。

**时间区分**：`occurredAt`/`detectedAt`/`savedAt`/`startedAt`/`finishedAt`；严格 UTC 保存、本地 UI 显示时区。跨设备时钟可能偏移，不能仅凭墙钟确定先后，需资源版本与事件序号。

## 健康与性能

- 核心存活 `liveness`、关键服务 `readiness`、后台任务 `progress/lastProgressAt` 分开。
- 监控核心 CPU/内存/磁盘剩余、插件加载失败、解析任务超时/重试、保存失败、AI Token/请求费用与缓存命中。
- 任务耗时单调时钟；事件发生时间使用 UTC。
- 插件状态：DISCOVERED/ACTIVE/FAILED/QUARANTINED 等，Core 不能因插件崩溃丢失诊断状态。
- 日志 IO 失败必须有受控降级，不得阻塞/无限重试导致业务连带死锁。

## 诊断事件（Incident）

统一 `incidentId`、`occurredAt`、`traceId`、`module`、`errorCode`、应用/插件/Schema/Git 版本、失败任务/文件版本；提取相关短窗日志、调用链、健康指标为**脱敏诊断包**。不默认包含整个文档正文、密钥或原始 Prompt。

## 错误分类（示意，最终为机器可检索规范）

- `ERR_RESOURCE_NOT_FOUND`, `ERR_PERMISSION_DENIED`, `ERR_PATH_OUTSIDE_ROOT`
- `ERR_ENCODING_UNSUPPORTED`, `ERR_RESOURCE_NOT_TEXT`（文本接口拒绝非 UTF-8 / 二进制内容，S5）
- `ERR_PLUGIN_INCOMPATIBLE`, `ERR_PLUGIN_CRASHED`, `ERR_PLUGIN_DEPENDENCY`
- `ERR_PARSER_TIMEOUT`, `ERR_FORMAT_UNSUPPORTED`, `ERR_PARSE_INVALID_INPUT`
- `ERR_DOCUMENT_VERSION_CONFLICT`, `ERR_SAVE_FAILED`, `ERR_OUTCOME_UNKNOWN`
- `ERR_JOB_CANCELLED`, `ERR_JOB_INTERRUPTED`, `ERR_DB_MIGRATION_FAILED`

稳定 errorCode 与 message 分离；message 可本地化，但不能替代稳定码。重要异常要记录首次/末次发生时间与次数；重试需退避上限与幂等保障。

## 日志隐私和大小上限

默认 INFO+WARN+ERROR，按模块短期开 DEBUG / trace；设轮转、上限和保留期；不要记录密钥、完整文件正文或无限堆栈。所有导出须可审核和脱敏。

## “排障完成”定义

能依据 `traceId` 找到：入口、实际版本、授权结果、插件、文件状态、保存结果、错误原因与是否安全可重试。不能仅说“模型返回成功”或“接口没有异常”。
