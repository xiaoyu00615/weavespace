# 工程阶段时间线（依赖式里程碑，不是工期承诺）

图：`../diagrams/05_工程路线.svg`。由于尚未确定研发人数、可用时间、技术探针结果，本计划采用**阶段与验收门槛**，不虚构具体日历完成日期。每阶段只有上阶段证据通过后才启动。

| 阶段 | 主要交付 | 前置 | 退出门槛 |
|---|---|---|---|
| **F0** 架构基线审查 | 产品范围、模块权威、契约草案、安全/日志/测试、ADR | 用户确认工程目标 | 审查遗漏/冲突、标记未决与不变量 |
| **P0** 最小技术探针 | 本地服务、两个插件、Command、Document Session、最简分屏 | F0 接受 | 正常 + 保存冲突 + 插件失败 + 日志追踪可复现 |
| **E01** 资源/存储底座 | 本地 Provider、根目录授权、稳定资源标识、监测 | P0 | 移动/重命名/权限/越界测试 |
| **E02** 编辑/插件 SDK | 生命周期、注册、Editor/Serializer、保存恢复 | E01 | 第三插件无需改 Core；脏文档卸载受保护 |
| **E03** Shell 工作区 | 文件树、标签、分屏、UI Slots、布局持久化 | E02 | 多视图同会话、重启恢复 |
| **E04** 自定义画布 | `.wcanvas`（暂定）、节点、连线、布局、保存 | E03 | 不依赖 AI 完成画布全流程 |
| **E05** 索引/知识 | 文件解析索引、来源、衍生/人工数据分离 | E01/E04 | 增量失效、人工确认不被覆盖 |
| **E06** AI 单文件 | 选区/文件上下文、建议补丁、批准、成本记录 | E02/E05 | 只修改授权范围，显示真实保存结果 |
| **E07** 外部 AI | Core Tool Registry → 最小 MCP / HTTP 适配 | E06 | 外部 AI 无裸文件和数据库权限 |
| **E08** 存储/网络扩展 | Git 插件、跨设备交接、LAN 只读、ACL | E03/E07 | 两设备、用户隔离与断线重同步 |
| **E09** 强化与发行 | 安全模式、备份恢复演练、发布打包、迁移 | 前序稳定 | 故障注入矩阵通过、发行检查 |

## 关键路径与并行建议

- 严格路径：F0 → P0 → E01 → E02 → E03 → E04 → E05 → E06 → E07。E08/E09 后期。
- 可并行准备：UI 草图迭代、样本数据与测试、解析器选型探针、文档站；不得提前修改已审查 Core 契约。
- 每阶段需 1 个状态报告（PASS/FAIL/BLOCKED + git commit + trace/测试摘要）即可；不强制制造大量 ZIP/冗余报告。
- 需求变更经过 ADR 和影响评估，不用为了功能追加无目标的核心层。

## 首轮只做什么

第一轮只读 F0 交付与审查；第二轮 P0 工程探针（纯小规模链路），暂不开发“全格式解析 / 全 AI / 多人网络”。
