# F0 复核：遗漏、重复职责、风险与结论

**范围**：仅根据已讨论的需求和公开技术参考做静态设计审查；**没有实际代码与性能验证**。不能声称“已完全没有遗漏”。

## 已识别并归属的容易遗漏机制

| 问题 | 归属（不另建新业务模块） | 处理要求 |
|---|---|---|
| 文件重命名后链接失效 | Resource | 稳定 ID 与路径映射；无法判定时人工确认 |
| 外部编辑与同步冲突 | Document + Storage | baseVersion / compare-and-swap |
| 同一个文件多个分屏 | Document + Workspace | 单会话、多视图 |
| UI 事件丢失/客户端掉线 | Events + Gateway | 版本/快照重同步 |
| 文件未变但解析器更新 | Knowledge/Index | 缓存键含 parser/config 版本 |
| AI 误把索引覆盖为人工结论 | Knowledge | Derived/Authored 分离 |
| 多 AI/局域网写入争用 | Command + Permission + Document | 权威写入与幂等收据 |
| 保存被中断 | Document/Persistence | 状态 UNKNOWN、草稿/恢复/核验 |
| 插件卸载时 dirty | Plugin Runtime + Document | 拒绝/协商关闭，不抛弃状态 |
| 解析恶意 HTML / ZIP | Permission + Plugin Runtime | 受限加载、沙箱、资源限额 |
| 依赖升级导致双电脑不一致 | Engineering | 锁文件、版本/Schema 迁移 |
| 诊断报告泄露文件/密钥 | Observability + Permission | 默认脱敏、最小收集、手动共享 |
| SQLite 被共享目录并发访问 | Host + Storage | 单主机权威，经 API 访问 |
| 配置覆盖设备私密信息 | Engineering + Permission | global/device/project/user/plugin 作用域 |

## 防重复架构责任检查

- **没有两个“保存服务”**：Serializer 负责编码，Document 负责会话/冲突，Storage 负责落盘原语。
- **没有两个“日志事实源”**：Operational Log / Audit / Business State 分层，统一时间/Trace 基础。
- **没有两个“AI 命令入口”**：内置 AI、外部 MCP、UI 都派发同一个 Core Command。
- **没有两套“项目资源树”**：远程仓库/云盘都通过 Resource/Provider 映射至统一文件树。
- **没有两套“布局与插件 UI”**：Shell 管布局，插件贡献 Slots/View，不重复开发 docking 系统。
- **不把 Cordis 和自研 PluginRuntime 两者同时完整实现**：P0 通过探针决定一套管理载体。

## 核心未决风险（不是遗漏，须显式登记）

1. **插件容器选型**：Cordis 特性虽强，但其适配成本与 TypeScript / React 宿主整合需 P0 实测；不能只依据 DSH 文档就锁定。
2. **跨文件事务**：不能承诺完全原子，需定义部分成功/未知与可恢复操作；E06 前评审。
3. **第三方插件沙箱**：同进程内置插件与第三方不可信插件的安全级别不同；安全模型分阶段落地。
4. **Docling / Python 依赖**：可能增大 Windows 安装成本；只在解析场景有足够价值时引入 Sidecar。
5. **Office 等复杂格式编辑**：不保证无损，不在 V0.1 承诺。
6. **LAN + AI Key**：多用户配额、滥用防护、远程外发和授权撤销需在开放 LAN 之前经过专项安全审查。
7. **性能/资源预算**：大规模媒体或项目（超万文件）需要真实基准测试，不设虚假性能指标。
8. **版权/隐私**：用户影视资产和截图仅用于本人项目，本包参考图在仓库公开前单独检查许可。
9. **时间线与成本**：里程碑依赖真实探针结果，实际工期与技术路线尚未确定。

## 结论

**可以进入 F0 用户签收和 P0 技术原型；不能直接宣称架构完全定稿或软件已准备生产使用。** 先固化边界与验收，具体框架/版本经过探针后冻结；后续每次扩展先查责任归属再提交 ADR。
