# UX-02C-05 文件树交互契约（菜单 / 工具栏 / 双击 / 键盘）

状态：**实施稿**（本轮实现与其提交见交付报告；本文件与代码同步维护）
范围：把已经实现的文件管理能力**组织成一套统一的交互**，不新增任何文件系统操作。

---

## 一、原有交互实现调查（实施前逐项读源码的结论）

| 关注点 | 本轮之前 | 当时的问题 |
|---|---|---|
| 右键菜单 | `ContextMenu.tsx`（portal + 键盘导航 + 子菜单）+ `TreeCommandsContext.tsx::menuItems` 装配 | **可用性在装配处现算**：`const usable = isSupported(...)`，再给每一项写 `hidden:` / `disabled:` / `whyNot`，同一个"不支持"有三种说法（`当前模式/项目不支持`、`链接节点不允许创建`、`目录暂不支持`） |
| 工具栏 | `TreeToolbar.tsx` 自己算 `usable`（`mode === 'live' && workspaceMode === 'multi' && READY`） | 与菜单**是两份判定**；两者对"能不能创建"的答案靠人工保持同步 |
| 项目根菜单 | 有（`origin: 'project-root'`，`ProjectList` 传 `projectId`） | 只有创建/标注/刷新；**没有**"修改项目显示名称""从工作台移除项目"，用户必须去行内找铅笔和 🗑 |
| 空白区域 | 有（`ProjectList` 的根 `<ul>` 上 `origin: 'blank'`） | 命令集靠 `hidden` 条件拼出；没有明确项目时也能点，点了只出一条"不支持"提示（先发意图再拒绝） |
| 项目显示名改名 | `ProjectList` 里 `useState` 的 `renaming/draft/error/saving` + 自己的 `submit` | 会话只活在项目根组件内：菜单打不开它、切换项目不会收敛、双击无法复用 |
| 项目移除 | `RemoveProjectEntry` 内部 `open` 状态 + 自带检查流程 | 入口固定在行上，菜单无法复用同一套检查与文案 |
| 双击名称改名 | **没有** | 单击会立即打开文件进入活动 View，而改名保护（UX-02C-02）要求"没有打开的标签"——两者直接冲突 |
| 键盘 | **没有** | F2 / Shift+F10 / 菜单键都不响应；也没有"只在树范围生效"的边界 |
| 菜单生命周期 | 只处理外部点击与 Escape | 切模式/切工作区/切项目后菜单**留在原地**，旧命令仍可点；执行前不检查目标是否还在 |
| 视口夹取 | `ContextMenu` 挂载后内联 `Math.min/max` | 规则不可断言（只能读 JSX 相信它） |

**结论**：底层能力（创建/改名/移动/隐藏/回收/标注/项目改名/项目移除）**都已经实现且被验收**。本轮不重写任何一条业务链路，只做三件事：把可用性收敛成一份矩阵、把入口铺满（根菜单/双击/键盘）、把失效守卫补齐。

## 二、统一命令矩阵

唯一来源：`apps/shell/src/state/tree-commands.ts::treeCommandMatrix(target, env)`。

```ts
export interface TreeCommandTarget {           // 菜单 / 工具栏 / 键盘共用同一个形状
  origin: 'file' | 'folder' | 'project-root' | 'blank' | 'link' | 'toolbar';
  projectId: string | null;
  nodePath?: string | null;
  entryKind?: 'file' | 'directory' | 'link';
  nodeHidden?: boolean;
  nodeAnchor?: string | null;                  // 打开菜单那一刻的资源锚（只作"还是不是这一行"）
}
export interface TreeCommandEnv {
  supported: boolean;                          // 与创建/改名/隐藏/回收的 isSupported 同一个值
  supportedExtensionCount: number;
}
```

`TreeCommandState = { visible, disabled, hint? }`，三条硬规则：

1. `visible: false` 表示**当前上下文完全不适用**（不是禁用），不渲染；
2. `disabled: true` 时**必须**带 `hint`（都是"为什么不能点"，不是功能说明）；
3. **可点的项一律不带 `hint`**——否则菜单上会出现"能点却写着不支持"的自相矛盾。

### 2.1 十四项命令 × 六类上下文

`✔` = 可见可用；`✖` = 不可见；`⊘` = 可见但禁用（带原因）。

| commandId | 文件 | 文件夹 | 项目根 | 空白区 | 链接 | 工具栏 |
|---|---|---|---|---|---|---|
| `rename` | ✔ | ✔ | ✖ | ✖ | ✖ | ✖ |
| `move` | ✔ | ✔ | ✖ | ✖ | ✖ | ✖ |
| `hide` | ✔ / ✖¹ | ✔ / ✖¹ | ✖ | ✖ | ✖ | ✖ |
| `unhide` | ✖ / ✔¹ | ✖ / ✔¹ | ✖ | ✖ | ✖ | ✖ |
| `trash` | ✔ | ⊘² | ✖³ | ✖ | ⊘⁴ | ✖ |
| `meta-alias` | ✔ | ✔ | ✔ | ✖ | ✖ | ✖ |
| `meta-tags` | ✔ | ✔ | ✔ | ✖ | ✖ | ✖ |
| `meta-color` | ✔ | ✔ | ✔ | ✖ | ✖ | ✖ |
| `new-file` | ✔ | ✔ | ✔ | ✔ | ⊘⁵ | ✔ |
| `new-folder` | ✔ | ✔ | ✔ | ✔ | ⊘⁵ | ✔ |
| `new-supported` | ✔ | ✔ | ✔ | ✔ | ⊘⁵ | ✖ |
| `refresh` | ✔ | ✔ | ✔ | ✔ | ✖ | ✔ |
| `rename-project` | ✖ | ✖ | ✔ | ✖ | ✖ | ✖ |
| `remove-project` | ✖ | ✖ | ✔ | ✖ | ✖ | ✖ |

1. 隐藏/取消隐藏**互斥**：由该行 `nodeHidden` 决定只出现其中一条（`A07` 锁定）。
2. 文件夹回收：`目录暂不支持（本阶段只处理普通文件）`——目录回收不在本阶段范围，**不伪造**一个能用的目录删除。
3. 项目根**不出现**回收：根不是磁盘条目，它的"移除"是 `remove-project`（解除注册），不是把目录扔进回收区（`A03` 锁定；`trash.ts` 里那条 `项目根不能移入回收区` 保留为纵深防御）。
4. 链接回收：`链接不能移入回收区（不会跟随链接）`。
5. 链接创建：`链接节点不能创建文件或文件夹（避免越过项目根）`——绝不沿链接创建。

模式不支持（Demo / Legacy / 静态 Multi / 项目非 READY）时：上表所有 `✔` 变成 `⊘`，`hint` 为
`当前模式或项目不支持（需要已授权的真实项目）`；创建与刷新在"没有明确项目"时改用
`没有明确的项目：请先选中一个项目`（**同一菜单内三条创建命令 + 刷新用同一句话**，`A04` 锁定）。

### 2.2 菜单顺序（产品行为，导出可断言）

```ts
ROOT_MENU_ORDER  = [new-file, new-folder, new-supported, rename-project,
                    meta-alias, meta-tags, meta-color, refresh, remove-project]
ENTRY_MENU_ORDER = [rename, move, hide, unhide, trash,
                    meta-alias, meta-tags, meta-color,
                    new-file, new-folder, new-supported, refresh]
```

根是"创建 → 显示名 → 标注 → 刷新 → 移除"，条目是"对这一个条目动手 → 标注 → 创建 → 刷新"。
同名命令位置不同是刻意的：根行没有改名/移动/回收这些"磁盘条目"命令。

### 2.3 三件必须分开的事

| 概念 | 命令 | 改什么 | 不改什么 |
|---|---|---|---|
| 项目显示名称 | `rename-project` → `actions.renameProject` | 工作区注册信息里的 `name` | 磁盘目录名、`workspaceKey`、标注名 |
| 资源标注名 | `meta-alias` → 资源元数据 | `metadata[]` 里的 `alias`（展示用） | 文件名、项目名 |
| 磁盘目录名 | **没有命令** | 用户自己在资源管理器里改 | 工作台永不修改 |

项目移除（`remove-project`）同样不是删除磁盘目录：它走 `removal-precheck` + `remove`，把项目从工作区注册里解除。

## 三、工具栏目标解析规则

`TreeToolbar` 不再自己判断"能不能新建"，只做两件事：

1. `treeCommandMatrix(toolbarTargetOf(activeProjectId), env)` 取 `new-file` / `new-folder` / `refresh` 三格；
2. 把 `disabled` 与 `hint` 画成 `disabled` + `title`（`aria-label` 是可访问名称）。

**目标目录仍然只有一份规则**：`state/create-entry.ts::resolveCreateTarget`。

| origin | 目标目录 |
|---|---|
| `blank`（空白区右键） | 当前项目里"最后明确选中的目录"（`selectedDirByProject`），没有则项目根 |
| `toolbar`（顶部按钮） | **同一个值**，同一个函数 |
| `file`（文件行右键） | 该文件的**父目录**——绝不会把文件路径当目录 |
| `folder`（文件夹行右键） | 该文件夹自身 |
| `link` | 拒绝（不解析） |

真实浏览器证据（`browser-verification.json` 的 `facts.createTargets`）：选中 `dir` 后，
空白区创建与工具栏创建发出的 `POST /api/files/create` 里 `parentDir` 都是 `"dir"`；
对根上的 `note.md` 右键创建，`parentDir` 是 `""`（不是 `note.md/`）。

无有效目标时**不发请求**：`beginCreate` / `toolbarRefresh` / 菜单 `refresh` 都先过
`targetProblem()` 与 `resolve()`，任一步不通过就只出提示。

## 四、双击名称改名与单击的仲裁

> **已由 R1 修订**：窗口 200ms → **500ms**，且仲裁器改为绑定**资源身份**。
> 见 `docs/30_UX-02C-05-R1_双击仲裁与资源身份修复.md`；本节保留首轮设计意图。
>
> **已由 R1.1 再修订**：身份引入三态（`verified` / `unsupported` / `unverified`），
> 且"残响"（身份变化后浏览器仍报 `detail ≥ 2`）不再被当成新手势起点。
> 见 `docs/31_UX-02C-05-R1.1_资源身份仲裁补强.md`。
>
> **已由 R1.2 再修订**：降级必须**两侧对称**（只有目标与当前都明确声明
> `unsupported` 且无矛盾锚才允许路径身份），且首屏整层替换不继承能力声明与根锚。
> 见 `docs/32_UX-02C-05-R1.2_身份降级与改名归属.md`。本节其余语义不变。

冲突是真实的：文件的单击会**立即**打开它进入活动 View，而改名保护
（`localStructureBlockers`，UX-02C-02）要求"这个文件没有打开的标签"。
若不区分单击与双击，双击的第一下已经把文件打开，改名必然被自己的保护挡住。

处理方式（`FileTreeRow` + `tree-commands.ts::createActivationArbiter`）：

- **名称文字区**（`.tree__name` / `.tree__alias`）的单击延后 `NAME_DOUBLE_CLICK_WINDOW = 500ms`（R1 起）；
  窗口内发生第二次点击则取消单击、只执行改名；
- **图标与行内空白**的单击**立即**激活（打开文件 / 展开文件夹 / 选中）；
- 键盘触发的 click（`detail === 0`）**立即**激活，不进窗口；
- 只在这一行确实能改名（`onRenameRequest` 存在）时才装配仲裁器；链接行、Demo/Legacy 行不装配，
  行为与改动前完全一致；
- 组件卸载 / 菜单关闭时 `cancel()` 撤掉在途单击（不再触发一次"打开"）。

**没有绕过任何会话保护**：双击改名走的是同一条 `structureRunner.submit({kind:'rename'})`，
`localBlockers` 照旧生效。若某行因为"文件已打开"而不能改名，双击会得到与菜单/F2 相同的拒绝提示，
而不是一条特权路径。

项目根名称双击 → `beginProjectRename`（只改显示名称）。

真实浏览器证据：`05-name-edit-dblclick.png`（输入行打开、状态栏无"已打开"、标签栏为空）
+ `browser-verification.json` 的 `D-02 双击后进入改名，且文件没有被打开`。

## 五、键盘交互

`treeKeyIntentOf({ key, shiftKey, inEditable, hasTarget })`，只绑在文件树根 `<ul>` 上。

| 按键 | 意图 | 行为 |
|---|---|---|
| `F2` | `rename` | 对"当前焦点行"执行 `beginRename`；已在命名中则不叠加会话 |
| `Shift+F10` / `ContextMenu` | `context-menu` | 在焦点行左下方打开同一个右键菜单 |
| `Escape` | `escape` | 关闭菜单（输入行自己的 Escape 由输入行处理），并把焦点还给触发行 |
| `Enter` | — | 由输入行处理（确认改名/创建） |

三条"不劫持"的硬约束：

1. `inEditable`（`input / textarea / select / [contenteditable="true"]`）为真 → 返回 `null`，
   树不抢任何按键（正文编辑器、搜索框、对话框一律不受影响）；
2. 没有焦点目标（`hasTarget === false`）→ 不给意图，F2 不对空气动手；
3. **不新增 `Delete` 等破坏性快捷键**：本轮没有删除语义。

禁用项不因键盘被执行：F2 先查矩阵 `rename`，`visible === false` 直接返回，
`disabled === true` 只出提示不执行（`C-04` 在演示模式下实测）。

## 六、菜单生命周期与失效守卫

### 6.1 关闭

| 触发 | 处理 |
|---|---|
| 外部 `pointerdown` | `onClose('other')`（不抢焦点） |
| `Escape` | `onClose('escape')`，焦点还给触发菜单的那一行 |
| 窗口 `blur` / `resize` | `onClose('other')` |
| 执行任一命令 | 先关闭再执行（`activate` 里 `onClose` → `command()`） |
| 切换模式 / 工作区 / 当前项目 | `identity` 变化 → `useEffect` 置空 |

### 6.2 位置

`menuPositionOf({x, y, width, height, viewportWidth, viewportHeight, edge})`：
靠近右/下边缘时向左/上翻转，始终留 `edge=8` 的边距；菜单比视口还大时也不产生负坐标。
纯函数，`H01/H02` 直接断言；真实浏览器 `H-03` 在右下角实测矩形完全在视口内。

### 6.3 失效

```ts
menuIdentityOf({ mode, workspaceMode, workspaceKey, activeProjectId })  // '\u0000' 连接
```

刻意**不含**逐层加载代次：否则用户刚打开菜单、一次分页刷新就会把菜单关掉。
任一"世界"变化都意味着菜单里的命令已经不属于当前界面。

执行前**再查一次目标**（`treeTargetProblemOf`）：

| 情形 | 文案 |
|---|---|
| 项目已不在工作区 | 该项目已不在工作区里，这个菜单已经失效 |
| 项目当前不可用 | 项目当前不可用，命令没有执行 |
| 该行已被移除/替换（层表里找不到） | 这一行已经被移除或替换，命令没有执行 |
| 同一路径换了对象（资源锚不同） | 这一行对应的对象已经变化，命令没有执行 |

`beginCreate` / `beginRename` / `openMove` / `toggleVisibility` / `refresh` / `toolbarRefresh` /
`trash` / `openMetadata` **全部**先过这道检查。`nodeAnchor` 只作"还是不是这一行"的前置判断，
不作身份、不作授权；权威仍是 Host。

不引入新的持久化台账，也不重实现回收区发送授权（那条仍在 `trash.ts` 的发送 gate 里）。

## 七、模块职责与复用关系

```
state/tree-commands.ts        纯 TS：矩阵 / 顺序 / 失效检测 / 键盘意图 / 菜单几何·身份 / 点击仲裁
components/TreeCommandsContext.tsx
                              编排：命令 id → 执行函数、执行前失效检测、菜单与命名会话生命周期
components/ContextMenu.tsx    呈现：portal、键盘导航、子菜单、夹取（调 menuPositionOf）
components/FileTreeRow.tsx    行原语：单击/双击仲裁、名称区判定、焦点上报
components/TreeBranch.tsx     节点 → 目标对象（右键 / 焦点 / 双击共用同一个）
components/ProjectList.tsx    项目根：根目标、显示名会话（状态在编排里）、树键盘入口
components/TreeToolbar.tsx    工具栏：只取矩阵三格，不自算可用性
components/RemoveProjectEntry.tsx
                              🗑 按钮 + 受控 RemoveProjectDialog（菜单与行共用同一套检查）
```

**没有被复制的东西**：

- 目标目录：`resolveCreateTarget` 一份（菜单/工具栏/键盘都走它）；
- 改名与移动：`createStructureRunner` 一份；
- 项目显示名：`actions.renameProject` 一份；
- 隐藏、标注、回收的可用性：仍由 `visibilityCommandState` / `metadataCommandState` /
  `trashDeleteCommandState` 各自回答，矩阵只做汇总与统一措辞；
- 磁盘操作：本轮**没有新增任何一个**。

`ContextMenu.tsx` 里原有的 `RESERVED_TREE_COMMANDS`（`delete-local` / `set-alias` /
`set-tags` / `set-row-color`）保持原样：它们是"尚未实现"的占位，不渲染。

## 九、未解决风险与 ARCH-01 待办

| 编号 | 风险 | 现状 | 建议 |
|---|---|---|---|
| C05-R1 | 双击改名的 500ms 窗口（R1 起；首轮为 200ms）是一处**有意的延迟**：名称上单击打开文件会比图标上慢 500ms | 已实测可接受（`D-01`～`D-06`）；窗口只作用于名称文字 | 若将来出现"单击打开必须零延迟"的要求，需要改成"双击后撤销已打开"的方案，那会与改名保护冲突，须先改 UX-02C-02 契约 |
| C05-R2 | 仲裁器依赖浏览器按 `click(1) → click(2) → dblclick` 顺序派发 | 真实 Chrome 已验；`detail >= 2` 不排定时器是**纵深防御**（变异 `C05-M6` 单独回退仍绿，如实记录） | 不为它加复杂度；若接入非标准输入设备再评估 |
| C05-R3 | 键盘 `Shift+F10` 在部分键盘布局上是"右键"系统键 | 已同时支持 `ContextMenu` 键 | — |
| C05-R4 | 矩阵把"项目根不出现回收"写成了 `origin !== 'project-root'` 的显式守卫，而 `trash.ts` 也有一条同义分支 | 两处判定，其中一处不会被走到 | ARCH-01：等 `trash.ts` 下次改动时把根的分支删掉，只留矩阵这一处 |
