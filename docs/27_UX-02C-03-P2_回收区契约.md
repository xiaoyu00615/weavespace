# UX-02C-03-P2 回收区契约（单文件可恢复删除 · P2-01 实施版）

> 状态：P2-01 已实施（无 UI）。本文件是**契约**，不是提案。
> 基线：`246146c` 之后新增；父提交见本轮 commit。
> 范围：单文件移入回收区 / 列表 / 恢复。**不含**目录递归、项目根删除、永久删除、自动清理、批量、UI。

## 1. 一句话模型

删除 = 「先落一条带身份的意图」+「同卷 rename 进 `.weavespace/trash/<opId>/payload`」+「把意图推进到 stored」。

三份事实各自独立、可互相核对：

| 事实 | 位置 | 回答什么问题 |
|---|---|---|
| 对象本体 | `.weavespace/trash/<opId>/payload` | 文件还在不在？还是不是同一个对象（`dev:ino`）？ |
| 自描述清单 | `.weavespace/trash/<opId>/manifest.json` | 这是哪个文件的、什么时候删的（配置丢失时的人工线索） |
| 状态机 | `workspace.json` v4 的 `trash[]` | 这次删除走到了哪一步、能不能恢复 |

## 2. 保留命名空间

- 目录：项目根层 `.weavespace/`（仅根层；`docs/.weavespace` 是用户普通文件夹）。
- 内部结构：`.weavespace/.ws-internal`（所有权标记）、`.weavespace/.gitignore`（内容 `*`，自忽略）、`.weavespace/trash/<opId>/{payload,manifest.json}`。
- **展示层**：`readDir`/`list` 在根层过滤；树、`total`、快照哈希、`hiddenCount` 都不含它。
- **访问层**：`open` / `/api/tree(dir)` / `files|directories/create` / `files/rename|move`（源与目标）/ `workspace/hide|unhide` / `trash/entry`（源）全部 `403 ERR_PATH_RESERVED`。
- 为什么不能只靠"路径越界"：那会让"放宽普通路径授权"变成进入内部目录的旁路。
- `.weavespace` 已存在但不是我们的（没有标记、或非空、或是链接/junction）→ `ERR_TRASH_UNAVAILABLE`，**绝不接管**。唯一例外：空目录（上次崩在 mkdir 与写标记之间）。

## 3. ConfigState v4

`version: 4` 新增 `trash: ConfigTrashEntry[]`；`checksum` 按**文件声明的版本**计算（v2 不含 `hidden`，v3 不含 `trash`），因此 v1/v2/v3 旧文件仍可读、可复算。发生变更时写回 v4。

```ts
interface ConfigTrashEntry {
  opId: string;            // [a-z0-9][a-z0-9-]{7,63}，同时是目录名与幂等键
  projectId: string;
  rootToken: string;       // 根被重新授权后记录失效
  originalPath: string;    // 规范化项目内相对路径（非保留段）
  entryKind: 'file';
  identity: string;        // dev:ino —— pending 就有，崩溃对账的唯一依据
  size: number;
  deletedAt: string;
  state: 'pending'|'stored'|'restoring'|'restored'|'aborted'|'conflicted'|'missing';
  restoredAt?: string;
  restoredTo?: string;
}
```

上限：`MAX_TRASH_UNRESOLVED = 500`（占文件的记录，满则拒绝新删除 `ERR_TRASH_FULL`）；
`MAX_TRASH_RECORDS = 2000`（配置体积，超出只淘汰 restored/aborted/missing 这类**不占文件**的终态记录）。

## 4. 状态机

### 4.1 删除

```
校验 → 屏障(准入独占+排空) → 会话检查 → entryFacts(普通文件?)
→ 写 pending(identity=I1) → trashEntry(provider, expectedIdentity=I1)
→ MOVED ? commit(stored) : (REJECTED ? commit(aborted) : 留 pending/202 UNKNOWN)
```

- 意图在**不可逆操作之前**落盘；写意图失败 → 409 `ERR_PERSIST_FAILED`，磁盘零变化。
- 移动 REJECTED → 尽力把记录收敛为 `aborted`（失败也不抛，交给对账）。
- 移动 UNKNOWN 或 stored 提交失败 → 202 + `opId`，**绝不重试**；对账据磁盘事实收敛。

### 4.2 恢复

```
记录 → 根令牌核对 → 对账(必须 stored) → 屏障 → 会话检查
→ 写 restoring → restoreEntry(provider, expectedIdentity=记录身份)
→ MOVED ? commit(restored) : (REJECTED ? 回退 stored : 留 restoring/202)
```

- 目标由记录决定（`originalPath`），客户端不能指定。
- 原位置已有同名对象 → `409 ERR_ENTRY_EXISTS`，**绝不覆盖**。
- 回收区对象身份不符 → `409 ERR_TRASH_STATE_CONFLICT`，零动作。

### 4.3 对账（`apps/server/src/trash.ts#reconcileTrash`，纯函数）

| 当前 | 回收区 | 原位置/目标 | 结论 |
|---|---|---|---|
| pending | 身份匹配 | 任意 | `stored`（移动已完成，补记） |
| pending | 存在但身份不符 | 任意 | `conflicted` |
| pending | 无 | 身份匹配 | `aborted`（移动未发生） |
| pending | 无 | 有但身份不符 | `conflicted`（**不判 missing**） |
| pending | 无 | 无 | `missing` |
| stored | 身份匹配 | 任意 | `stored` |
| stored | 存在但身份不符 | 任意 | `conflicted` |
| stored | 无 | 身份匹配 | `restored`（对象已回到原路径） |
| stored | 无 | 有但身份不符 | `conflicted` |
| stored | 无 | 无 | `missing` |
| restoring | 有（身份匹配） | 目标无 | `stored`（回退，可重试） |
| restoring | 有（身份不符） | 目标无 | `conflicted`（不得回退） |
| restoring | 有 | 目标有 | `conflicted` |
| restoring | 无 | 身份匹配 | `restored` |
| restoring | 无 | 有但身份不符 | `conflicted` |
| restoring | 无 | 无 | `missing` |

纪律：**探针失败 = conflicted**（"看不清"不等于"没有"）；终态不再判定；对账**从不删文件**。

触发：Host 启动（只扫 pending/stored/restoring）+ 每次 `GET /api/trash`。

## 5. Host API

全部：T1 令牌 + POST 显式 Origin + 项目级授权 + G-DISK 门禁；响应不含绝对路径。

| 端点 | 说明 |
|---|---|
| `POST /api/trash/entry` `{projectId, path, opId}` | 200 `{status,opId,path,entry}` / 202 UNKNOWN / 400 类型不支持 / 403 保留路径 / 409 会话占用·目标冲突·opId 冲突·容量满·未持久化 |
| `POST /api/trash/restore` `{projectId, opId}` | 200 / 202 / 409（目标已存在·状态冲突）/ 404 记录不存在 |
| `GET /api/trash?projectId=` | 读取前先对账；返回 `{count, entries[], orphaned, notice?}` |
| `GET /api/trash/op?opId=&projectId=` | 必须声明 `projectId` 并做该项目的 `read` 授权；返回 `{outcome, state}`。`pending`/`restoring` → **202 + outcome:`unknown`**；跨项目 → 404（不确认存在）；项目已撤销 → 403（不回传路径/归属） |

**重放语义（P2-04）**：同一 `opId` 重试**绝不**再次移动文件，且按已有记录的真实状态回应——
`stored` → 200 `APPLIED`；`pending`/`restoring` → 202 `UNKNOWN`；`aborted`/`conflicted`/`missing` → 409
`ERR_TRASH_STATE_CONFLICT`。旧实现无条件回 200 `APPLIED`，等于把未确认/失败谎报成成功。

`POST /api/projects/remove` 在响应中追加 `trashRetained` 与 `notice`：撤销**不会**删除回收记录，
文件仍在原项目目录里，但应用内不再提供恢复入口。

## 6. 身份与并发

- 复用 `withStructureChange`（准入独占 + `waitForZeroOps`）与 `withStructureDiskOp`（能力凭据）。
- 复用 `structureSessionBlockers`：任何活动 View / dirty / SAVING / OUTCOME_UNKNOWN / CONFLICT 一律 409，
  Shell 侧另有 `localStructureBlockers` 作为第二道门。
- Provider 在 rename **之前**再核一次源身份；`expectedIdentity` 不符 → `ERR_ENTRY_SOURCE_CHANGED`，
  替换对象毫发无损。
- 目标用 `open(...,'wx')` 排他占位，并且 **rename 之前复核占位归属**（R1 / P1-01）：
  `owned` 继续；`missing` 重新排他占位一次；`foreign`（同名 0 字节文件也是 foreign，按 `dev+ino` 判定）
  一律 `ERR_ENTRY_EXISTS` 且不碰外部对象；探测异常 → UNKNOWN。
- **未消除的窗口（如实披露）**：最后一次归属复核与 `rename` 之间仍有竞争；占位可被外部删除后替换。
  与改名/移动路径同源，本阶段未消除。**不得**把它描述成"已经完全消除外部进程竞争"。

## 6.1 内部目录硬约束（R1 / P1-02、P2-05、P2-06）

- 所有权标记 `.ws-internal`：读前核验类型（拒绝符号链接/重解析点/非普通文件），拒绝 `nlink > 1`
  （硬链接 = inode 被根外共享）；读取经已打开句柄并与 `lstat` 身份比对。
- 标记的建立/更新一律"同目录临时文件 + 排他创建 + 身份核验 + rename"，**永不**对已存在的
  标记直接 `writeFile`（那会跟随链接写穿到根外）。
- `.gitignore` 每次初始化都核验/补写（`*`），因此"标记已写、gitignore 未写"的中断可自愈。
- `trash/<opId>` 内部只允许 `payload`（普通文件）与 `manifest.json`（magic + opId + identity 自洽）；
  出现陌生文件、链接、目录 → `ERR_TRASH_UNAVAILABLE`，不覆盖、不删除、不纳入事务。
- 归属不明时把回收区整体判为不可用，而不是"重建标记"。

## 6.2 记录 CAS（R1 / P1-03）

- `beginTrash` 重放必须核对 `opId + projectId + rootToken + originalPath + identity` 全部相同；
  任一不符 → `ERR_OP_ID_CONFLICT`（跨项目并发不得互相污染）。
- `commitTrashState` 必须同时匹配 `projectId / rootToken / originalPath / expectIdentity` 且状态 ∈ `expect`，
  否则 `skipped-conflict` 且零写入。**不存在**只凭 `opId` 更新记录的旁路。

## 6.3 恢复前的只读完整核验（R2 / R2-03）

恢复不调用任何初始化流程（不建目录、不补 `.gitignore`、不重写标记），只做**只读**核验：

1. `.weavespace` / `trash` / `trash/<opId>` 逐级：位于项目根内、是真目录、非符号链接/重解析点；
2. `trash/<opId>` **白名单**：只允许 `payload` 与 `manifest.json`；
   陌生文件、陌生目录、`payload` 缺失、`manifest.json` 缺失 → `ERR_TRASH_UNAVAILABLE`
   （`payload` 缺失时 `ERR_TRASH_RECORD_NOT_FOUND`），**不覆盖、不删除、不接管**；
3. `manifest.json` 经"句柄读取 + 身份比对"读入（与标记同一套判定，拒绝链接/重解析点/`nlink > 1`），
   且必须与本次恢复事务逐字段一致：
   `magic` / `opId` / `originalPath`（按平台大小写规则比较）/ `entryKind === 'file'` /
   `identity`（与记录身份一致，不符 → `ERR_TRASH_STATE_CONFLICT`）/ `size`（非负**安全整数**）/
   `deletedAt`（严格 ISO）。
4. **字节数三方一致**（R2-Supplement / A1）：`manifest.size` = 配置记录 `size` = 磁盘上 `payload` 的真实大小。
   任何一处不符 → `ERR_TRASH_STATE_CONFLICT`。两项比较分别放在两处（清单↔记录在只读核验里，
   清单↔磁盘在 `restoreEntry` 里），每项只放一处，避免一处被改坏时另一处"顺手"兜住。
5. **时间戳严格格式**（A2）：`deletedAt` 只接受 `new Date().toISOString()` 的写法
   ——`YYYY-MM-DDTHH:mm:ss.sssZ`，且 `new Date(v).toISOString() === v`（往返一致）。
   `+00:00` 偏移、省略毫秒、省略 `Z`、自然语言日期、`2026-02-31` 这类"能解析但不存在"的值
   一律拒绝（`ERR_TRASH_UNAVAILABLE`）；只靠 `Date.parse()` 不够——它接受太多非约定写法。

## 6.4 占位与内部写盘的失败语义（R2 / R2-02、R2-04）

- 回收、恢复、复原占位**共用同一段实现**（`reservePlaceholderOwned`）：
  `open('wx')` 成功即视为"磁盘已有副作用"。此后 `stat` 取不到身份、`close` 失败、
  占位归属无法证明 → 一律 UNKNOWN（重试 `close` 只是尽力而为，**不得**因此改报成功）；
  只有 EEXIST 或"确认没建出占位"的 open 失败才是 REJECTED。
  close 失败时只清理 `dev+ino` 能证明属于自己的占位，外部对象一律不碰，且**不执行 rename**。
- 内部文件（`.ws-internal` / `.gitignore`）写入在 `rename` **之前**复核临时文件：
  存在、普通文件、非链接/重解析点、`dev+ino` 一致、`nlink === 1`。任一项不满足 → 不 rename、
  不覆盖目标、只清理可证明归属的临时文件。

## 7. 已知限制

| 限制 | 说明 |
|---|---|
| 无永久删除/无自动清理 | 回收区只增不减；满 500 条后必须先恢复 |
| `git clean -xdf` | 会连同 `.weavespace` 一起清掉（`.gitignore` 只防提交，不防清理） |
| 项目撤销 | 记录保留、文件保留、入口消失（响应有 `trashRetained` 提示） |
| 降级不兼容 | v3 二进制读不了 v4 配置（与 v2→v3 相同的单向升级） |
| 目录/链接 | 一律 `ERR_TRASH_KIND_UNSUPPORTED`（P3 再议目录） |
| 长路径 | payload 固定名 `payload`，不继承原文件名，规避 260 限制 |
| TOCTOU 窗口（未消除） | 三处"核验 → 动作"仍有竞争：`lstat → unlink`（清理占位/临时文件）、`lstat → rename`（安装内部文件/覆盖占位）、`复核临时文件 → rename`。只在"外部进程已能写项目目录"时成立，且不扩大其权限；Node 未暴露 `unlinkat`/`RENAME_NOREPLACE`/句柄级删除，本阶段不引入原生依赖。详见 `docs/evidence/ux-02c-03-p2-01-r2/notes.md` §4 |
