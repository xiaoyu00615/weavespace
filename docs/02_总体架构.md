# 总体系统架构（Headless Core + 插件 + 多客户端）

参见 `../diagrams/01_系统全景.svg`、`02_模块依赖.svg`、`03_编辑操作序列.svg`。

## 四层分离

**客户端层**：浏览器 Shell，负责标签、文件树、可组合 UI Slots、布局和只呈现客户端模型；不直接访问 SQLite 或可信文件系统。

**入口/适配层**：localhost HTTP / IPC 是首版入口；未来 LAN Gateway（明确启用、认证、ACL）与 MCP / 外部 AI 适配器；它们都调用同一应用服务接口。

**Headless Core / 应用服务层**：资源定位、Document Session、命令/权限、插件注册、任务调度、写入协调、事件版本；可以无图形 UI 测试。

**执行/数据层**：Storage Provider、文件 Parser/Viewer/Editor/Serializer、持久化存储、索引、画布与模型适配器。每种能力只在其拥有者处实现。

**横向约束**：日志、Trace/指标/事件审计、配置、契约测试，围绕调用执行而非额外提供第二套业务入口。

## 调用方向（必须遵守）

- Shell → Client API → Command / Query Facade → 资源与文档/插件/存储；反向通过版本化事件/订阅传播状态。
- 插件调用其他服务通过 Capability Service / 公共契约，不允许直接 import 其他插件的实现目录。
- 持久化数据库仅由其负责服务访问；跨客户端不直接共享数据库文件。
- AI 与人工采用同样的 Command Bus；额外策略因 actor、scope、risk 不同而不同。
- UI Slots 承载呈现和交互，业务权威状态由 Core/文档会话管理。
- 安全检查在**服务器操作边界**执行，前端按钮隐藏不是权限措施。

## 状态与责任不混淆

| 状态 | 权威拥有者 | 可否删除重建 |
|---|---|---|
| 源文件 Source | Storage Provider 对应文件 | 否，需用户明确操作 |
| Document Session 编辑缓冲 | Document Service | 未保存前不能丢失，需恢复策略 |
| 解析/索引 Derived | Index Service | 可以按输入/解析版本重建 |
| 用户确认知识、画布 Authored | Knowledge / Document 对应存储 | 不能由索引任务覆盖 |
| 布局/面板 Presentation | Workspace Service | 可恢复，丢失不等于源文件丢失 |
| 命令结果/任务状态 | Command/Job Owner | 不依赖普通日志推断 |
| 操作审计 Audit | Audit Service | 独立保留策略，不与调试日志混用 |

## 外部与远程设计

本机默认绑定 `127.0.0.1`；未来 LAN 必须显式开启，采用身份验证、传输保护、资源级授权。HTTP / MCP / UI 不直通解析器内部对象。网络断线后依据版本/快照恢复，而不是默认事件不会丢。

## 容错限制

单插件故障不拖垮其他模块是目标；对非可信插件需要进程/沙箱隔离。首版若暂用同进程插件，必须如实记录无法保证强隔离，而不是仅凭 try/catch 声称已隔离。
