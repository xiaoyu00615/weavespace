## 4. 接口变更提案

### 4.1 `GET /api/tree`（新，只读，分页）

```http
GET /api/tree?projectId=notes&dir=docs/design&cursor=200&limit=200
```

- `projectId`：Multi 必填；Legacy 省略（沿用单根 Provider）。
- `dir`：**项目内相对路径**，正斜杠分隔，省略 = 根。
- `cursor`：不透明游标，省略 = 第一页；当前实现是十进制偏移量，客户端不得解析。
- `limit`：**每页**条数，缺省 200、范围 1–2000；它不是"单层可见上限"——
  必须靠 `nextCursor` 继续加载**直到该层全部可见**（契约 B.2.1）。
- 响应：

```jsonc
{
  "status": "APPLIED",
  "entries": [ { "id": "dir:notes/src", "name": "src", "kind": "folder", "relPath": "src", "extension": "" } ],
  "page": { "limit": 200, "cursor": null, "nextCursor": "200", "total": 2001 }
}
```

- 无需 `X-WS-Token`（与 `/api/resources` 一致：只读、同源、回环）；但必须：
  1. 项目存在且 `READY`（否则 404 / 503）；
  2. 项目级读授权（`permission.authorize`，`providerId: local:<projectId>`）；
  3. `withDiskOp` 包裹（屏障期拒绝）；
  4. 根连续性检查（失败 → 503，不回传路径）。
- `dir` 校验：拒绝绝对路径、盘符、UNC、`..` 段、NUL、空段，→ `400 ERR_COMMAND_INVALID`，零 IO。
- `dir` 指向链接节点 → `400 ERR_DIR_IS_LINK`（lstat 复核，零跟随，见契约 B.5）。
- `cursor` / `limit` 非法 → `400 ERR_COMMAND_INVALID`，零 IO；`cursor` 超出总数 → `200` 空页。
- 目录读取失败 → `403 ERR_DIR_UNREADABLE`（**不是** `ERR_PERMISSION_DENIED`，见契约 B.6）；
  目录不存在 / 不是目录 → `404 ERR_RESOURCE_NOT_FOUND`。

### 4.3 `StorageProvider.readDir`（新端口）

```ts
export type DirEntryKind = 'folder' | 'file' | 'link';
export interface DirEntry {
  name: string;
  kind: DirEntryKind;
}
readDir(dir?: string): Promise<DirEntry[]>;
```

- 复用 `resolveInBoundary` → `assertRootContinuity` → `readdir(withFileTypes)`。
- **错误必须上抛**（R1 修订后的映射，逐条与契约 B.6 对应）：
  | 底层错误 | 错误码 | HTTP |
  |---|---|---|
  | `ENOENT` | `ERR_RESOURCE_NOT_FOUND` | 404 |
  | `ENOTDIR`（路径是文件） | `ERR_RESOURCE_NOT_FOUND` | 404 |
  | `EPERM` / `EACCES` / `EBUSY` / `EIO` / 其他目录读取失败 | **`ERR_DIR_UNREADABLE`** | 403 |
  | 路径越界 / 悬空重解析点 / NUL / 绝对路径 | 既有 `ERR_PATH_OUTSIDE_ROOT` 等 | 403 / 400 |
  | 根身份漂移 | 既有 `ERR_ROOT_CHANGED` 等 | 503 |
- **不得**把 `EPERM/EACCES` 复用成 `ERR_PERMISSION_DENIED`：那是 WeaveSpace 的授权判定码，
  与"磁盘不让读"是两种事实（契约 B.6）。因此 `readDir` 使用独立的目录错误映射，
  不复用写入链路的 `toStorageError`。
- `Dirent.isSymbolicLink()` → `kind: 'link'`（Windows junction 由同一判定覆盖，现行 `list()` 已依赖这一点）。
- 结果按 `name` 升序（稳定），排序语义在 `tree.ts` 再做"目录/链接在前"。
- 单层不必自己做上限；分页在 `server.ts` 应用（便于返回 `nextCursor` / `total`）。

### 4.4 节点字段取舍

- 服务端 DTO 用 `relPath`；Shell 侧 `ResourceNodeState.path` 继续承载"打开时用的相对路径"，两者含义相同，**映射一次**，不做双字段并存。
- **删除** `kind: 'markdown' | 'text'`：`kind` 只保留 `folder | file | link`。这是修掉 §2.4 的类型漂移。
- **新增** `extension` 的实际赋值（服务端 `extensionOf(name)`）。

## 9. UX-02B-04B（移除 / 状态提示 / 恢复）

### 9.1 范围

移除 UI、阻断原因呈现、`REVOKE_UNKNOWN` / `REVOKED_PENDING_CONFIG` / `UNAVAILABLE` 的用户可见文案、重启后项目列表恢复。

### 9.2 实施步骤

1. `POST /api/projects/removal-precheck` + `POST /api/projects/remove`（Runtime 已就绪）。
2. 移除确认模态（`confirm: 'remove-from-workspace'`），文案必须写"不删除磁盘内容"。
3. 阻断原因映射：`ACTIVE_VIEWS` / `DIRTY` / `SAVING` / `OUTCOME_UNKNOWN` / `CONFLICT` / `IN_FLIGHT_DISK_OPS` / `DRAIN_TIMEOUT` → 可读提示 + 引导动作。
4. 移除后：该项目从树中消失，已打开标签标记 STALE（草稿可读，G-DRAFT）。
5. 结果确认：`opId` 查询（`GET /api/projects/op`）→ `APPLIED` / `UNKNOWN` 展示，`UNKNOWN` 只重拉列表并提示人工确认，**不自动重试**。
