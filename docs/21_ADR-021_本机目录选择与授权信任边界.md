## 1. 背景（事实）

| # | 事实 | 依据 |
|---|---|---|
| F1 | 项目配置只能来自启动参数 `--workspace <file>`，进程内读取一次 | `packages/project-registry/config.ts:5-8` |
| F2 | 服务端已拒绝 body 中的 `rootDir` / `root` / `actorId` / `providerId` | `apps/server/src/server.ts:291-309` |
| F3 | 写请求已校验 `Host`、`Origin` 白名单、`Sec-Fetch-Site`；服务只绑回环地址 | `server.ts:220-228, 594-630` |
| F4 | 浏览器**无法**取得本机绝对路径：`<input webkitdirectory>` 只给相对文件名；File System Access 只给不透明 handle；拖拽目录同样不给路径 | 平台能力，非本仓库实现 |
| F5 | 新项目根必须真实存在、非 UNC/设备路径、非重解析点、`ino` 可用 | `packages/project-registry/root-status.ts:58-100` |
| F6 | 根目录不会被自动创建（Registry 无 mkdir 路径） | `root-status.ts:6-10` |

推论：**"让网页选文件夹"在技术上不可能安全成立**——网页能提供的只有目录名或 handle，任何"路径字符串"都必须由 Host 自己取得，否则就是"接受网页传入的任意绝对路径"，正是 `docs/12` 与既有契约禁止的行为。

## 2. 问题

产品目标要求用户"在网页里添加本机文件夹"。这与 F1 的冻结声明冲突，且必须回答：

1. 浏览器怎样才能安全触发**本机**文件夹选择器？
2. 如何证明"这个目录确实经过本机用户明确授权"，而不是网页伪造？
3. 如何防止恶意网页 / 跨站请求 / 伪造凭据绕过确认？

## 3. 决策

### 3.1 三项判定彼此独立，不可互相替代

| 判定 | 名称 | 载体 | 证明 | 不能证明 |
|---|---|---|---|---|
| **T1** | 请求来源可信 | 回环绑定 + `Host` 头 + `Origin` 白名单 + `Sec-Fetch-Site` + `X-WS-Token` | 请求来自本机 Host 服务的页面 | 用户是否真的选了目录 |
| **T2** | 变更意图已被本页消费 | `intentId`（一次性、单飞、120s TTL、绑定 actorId） | 这一次变更请求确实由当前页面会话发起、且未被重放 | **不是**"人类点了按钮"的证明——页面内脚本同样能发；也不证明选中的是本机哪个目录 |
| **T3** | 目录确实经本机确认 | **Host 进程内** `FolderPicker` 的返回 + `inspectProjectRoot()` 复核 | 本机用户在系统对话框点了"确定"（这是唯一的人工确认证据） | 与 T1/T2 无关 |

**Session Token 只承担 T1（请求鉴权 / CSRF 防护）。它不表达、也不能表达目录授权。**

> T2 的准确定位：`intentId` 只解决**重放与并发**（同一意图不会被用两次、同一时刻只有一个 pending），因此它是"请求新鲜度"凭证，不是"用户点过按钮"的凭证。若有人在已授权的页面上下文里用脚本调用，T2 依然成立——这正是为什么 T3（Host 侧系统对话框 + `inspectProjectRoot` 复核）不可缺省，也是为什么"网页传路径"永远不能替代它。

### 3.2 路径永不经过 HTTP

- 请求体只允许"意图"字段：`intentId`、`requestId`、`projectId`、`name`、显式确认标记。
- 以下字段出现在任何请求体即 **400 `ERR_COMMAND_INVALID`**，且不产生任何 IO：
  `rootDir` / `root` / `path` / `directory` / `canonicalRoot` / `rootToken` / `grantSource` / `actorId` / `providerId`。
- 授权凭据 `(canonicalRoot, rootToken, grantedAt, grantSource)` **只由 Host 内部生成并写入持久配置**，任何响应都不回传。

### 3.3 选择器由 Host 拥有

`FolderPicker` 端口（`apps/server/src/folder-picker.ts`，新）：

```ts
export interface PickedFolder { readonly absolutePath: string }
export type PickOutcome =
  | { status: 'picked'; folder: PickedFolder }
  | { status: 'cancelled' }
  | { status: 'unavailable'; detail: string };   // 无 GUI / 被策略拦截 / 不可交互

export interface FolderPicker {
  pick(options: { timeoutMs: number }): Promise<PickOutcome>;
}
```

适配器：

| 适配器 | 适用 | 行为 |
|---|---|---|
| `windows-powershell` | Windows 桌面（默认） | 见 §3.4 |
| `stdin-prompt` | 无 GUI 但可交互的终端 | Host 在终端打印一次性口令并读取路径；**仅当 stdin 是 TTY** |
| `fake` | 测试与 CI | 返回预置路径或取消；禁止生产使用 |

无适配器可用 → **fail-closed**：`501 ERR_PICKER_UNAVAILABLE`，提示改用静态模式 `--workspace`。**绝不退化为"让用户在网页里输入路径"。**

### 3.4 Windows 适配器的进程调用安全（P1-05）

```text
powershell.exe -NoProfile -NonInteractive -STA -ExecutionPolicy Bypass -Command <固定脚本常量>
```

- 用 `child_process.execFile`（**不是** `exec`），`shell: false`，`windowsHide: true`，`timeout: 120_000`，`maxBuffer: 64_000`。
- 脚本是**代码内常量**，不含任何用户输入插值；不写临时 `.ps1` 文件（规避执行策略与编码问题）。
- 脚本内容：`Add-Type System.Windows.Forms` → `FolderBrowserDialog`（`ShowNewFolderButton=$false`）→ 用户确认后把 `SelectedPath` 以 **UTF-8 → Base64** 写 stdout（规避控制台代码页导致的路径乱码）。
- 退出码语义：

| 退出码 | 含义 | 处理 |
|---|---|---|
| 0 + 非空 Base64 | 已选择 | 解码 → UTF-8 → §3.5 复核 |
| 1 | 用户取消 | `cancelled`，无副作用 |
| 超时 / 被 kill | 视为取消 | `cancelled` |
| 其他 / 空输出 / 解码失败 / 找不到 powershell | 选择器不可用 | `501 ERR_PICKER_UNAVAILABLE` |

- 约束：单次只允许一个选择器进程（`single-flight`）；上一个未结束时新请求 409。
- **风险（假设）**：EDR 可能拦截 PowerShell 启动；`-STA` 下对话框可能不在前台。若实测不可用，回落 `stdin-prompt`，不改变安全边界。

### 3.5 复核（Admission）——授权只能由复核结论产生

`RootAdmission`（Host 内，纯判定）：

1. `inspectProjectRoot(path)` 必须 `READY`（存在、目录、非 UNC、非重解析点、`ino` 可用）。
2. 与现有全部项目比对：重复根 → `ERR_PROJECT_DUPLICATE_ROOT`；嵌套（A⊂B 或 B⊂A）→ `ERR_PROJECT_NESTED_ROOT`（含 Windows 大小写折叠）。
3. `projectId` 由 Host 生成：`slug(name)` 匹配 `^[a-z0-9][a-z0-9_-]{0,31}$`，冲突或已签发（含已撤销）→ 追加序号；**中文名等无法 slug 时用 `project-<n>`**。
4. 生成 `grantSource: 'os-dialog'`、`grantedAt`、`canonicalRoot`、`rootToken`。
5. 通过后才进入 ADR-022 的事务。

## 4. 准入与拒绝矩阵

端点（Host 目前只接受 `GET`/`POST`，其余 405，故不引入 PATCH/DELETE）：

| 端点 | T1 | T2 | T3 | 静态 Multi / Legacy | 拒绝码 |
|---|---|---|---|---|---|
| `GET /api/session-token` | 同源 | — | — | 也提供（只读页面也需要） | — |
| `POST /api/projects/pick` | 需 token | 消费 `intentId` | 启动选择器 | **501** | 403 / 409 / 410 / 501 |
| `GET /api/projects/pick?requestId=` | 需 token | — | — | 501 | 403 / 404 / 410 |
| `POST /api/projects/removal-precheck` | 需 token | — | — | 501 | 403 |
| `POST /api/projects/rename` | 需 token | — | — | 501 | 400 / 403 / 404 |
| `POST /api/projects/remove` | 需 token | 需显式 `confirm:'remove-from-workspace'` | — | 501 | 403 / 404 / 409 |
| `GET /api/projects/op?opId=` | 需 token | — | — | 501 | 403 / 404 |

- Legacy 与静态 Multi 对上述"变更类"端点一律 **501 `ERR_COMMAND_UNSUPPORTED`**，其余行为零变化（§7）。
- 未带 `X-WS-Token`、`Origin` 不在白名单、`Origin: null`、`Sec-Fetch-Site` 非 `same-origin`/`none` → 403，且**不弹对话框**。

## 5. 威胁模型与必须通过的安全测试

威胁模型**排除**"已能读写本机文件系统的本地用户"（其本可直接改配置或用任意工具），只针对**网页与远程请求**。

| ID | 场景 | 期望 |
|---|---|---|
| S-01 | 跨源页面 POST `/api/projects/pick` | 403，无对话框，无进程创建 |
| S-02 | 无 `Origin` 的浏览器写请求 | 403 |
| S-03 | `Origin: null`（sandbox iframe / `file://`） | 403 |
| S-04 | 伪造/随机 `X-WS-Token` | 403 |
| S-05 | 复用已消费的 `intentId` | 410，无对话框 |
| S-06 | `intentId` 超过 120s | 410 |
| S-07 | 两次并发 pick | 第二次 409；只创建一个进程 |
| S-08 | 用户取消 | 200 `cancelled`；配置与内存零变化 |
| S-09 | 选择器异常 / 无 PowerShell / 超时 | 501；零副作用；不索取路径 |
| S-10 | body 携带 `rootDir` / `rootToken` / `grantSource` / `canonicalRoot` | 400，零 IO |
| S-11 | 选择的目录是 UNC / 重解析点 / 文件 / 不存在 | 422 + 对应 reason，零写入 |
| S-12 | 选择的目录与现有根重复或嵌套（含大小写等价） | 409 / 422，零写入 |
| S-13 | Host 在选择器未返回时重启 | pending 丢失 → 客户端 410，需重试；无半成品配置 |
| S-14 | 加项目后 `/api/projects` 与 `/api/health` 响应 | 不含任何绝对路径 / rootToken / providerId（延续 `tests/37 WK-04`） |
| S-15 | legacy / 静态 multi 调变更端点 | 501，且 `/api/projects` 行为不变 |
| S-16 | 添加成功后立即 `/api/resources?projectId=<new>` | 200 且返回该目录树（无需重启） |

## 6. 失败 / 取消 / 崩溃后的恢复

| 阶段 | 崩溃/失败 | 磁盘 | 内存 | 恢复 |
|---|---|---|---|---|
| 启动选择器前 | 校验失败 | 未变 | 未变 | 直接重试 |
| 选择器运行中 | 进程被杀 / 超时 | 未变 | 未变 | 视为取消；用户重试 |
| 复核失败 | 重复/嵌套/身份不支持 | 未变 | 未变 | 返回原因，不做部分登记 |
| 事务提交中 | 见 ADR-022 §5 | 见 ADR-022 | 见 ADR-022 | 以磁盘为权威 |

## 7. 兼容性

| 模式 | 启动方式 | 变更能力 | 既有断言 |
|---|---|---|---|
| Legacy 单根 | `<root> [port]` | 无（全部 501） | 完全保留 |
| 静态 Multi | `--workspace <file>` | 无（全部 501） | 完全保留；`tests/25:116` `version()===1` 不变 |
| 托管 Multi | `--workspace-store <dir>`（新） | 有 | 新增用例，不改既有 |

静态模式不读也不写 `--workspace-store`，两者同时给出 → 启动失败（互斥）。

## 8. 本轮不实现（边界）

- 不做目录扫描/自动发现项目，不把子目录自动注册为项目。
- 不做拖拽目录授权（拖拽不提供路径）。
- 不做 macOS/Linux 原生选择器（首版只 Windows；其他平台走 `stdin-prompt` 或静态模式）。
- 不做网络共享 / UNC 根（继续拒绝）。
- 不做 rebind（A2，ADR-023 只冻结状态机）。
- 不做"网页内输入路径"的兜底入口。

## 9. 待用户批准点

1. 接受"浏览器永远不传路径、选择器由 Host 拥有"作为**不可协商的安全不变量**（建议同时写入 `docs/12`）。
2. 接受 `windows-powershell` 作为首版默认选择器实现（含 EDR 风险）。
3. 接受静态模式与托管模式的**启动参数互斥**与变更端点 501 语义。
4. 接受"局部取代 `docs/20 §2.1`"，而非改写原文。
